# 運用ガイド — 更新・バックアップ・復元・アンインストール

導入したあとの操作をまとめています。機械ごとの入口は
[Mac](setup-macos.md) / [Windows](setup-windows.md) / [Raspberry Pi](setup-raspberry-pi.md) を見てください。

| | 場所 |
|---|---|
| Mac | `ホーム/laser-editor` |
| Windows | `C:\Users\<あなた>\laser-editor` |
| Raspberry Pi / Linux | `/opt/laser-editor` |

以下ではこれを **インストール先** と呼びます。

---

## 更新する

**インストーラをもう一度実行するだけです。** 設定もデータもそのまま引き継がれます。

| 機械 | 操作 |
|---|---|
| Mac | ターミナルで導入時と同じ 1 行 |
| Windows | `install.bat` をダブルクリック |
| Raspberry Pi / Linux | SSH で導入時と同じ 1 行 |

### どの版が入るかを決める（任意）

インストール先の `.env` に 2 つの設定があります。

```
LASER_IMAGE_TAG=latest
#LASER_IMAGE_DIGEST=sha256:...
```

- **`LASER_IMAGE_TAG`** … 人が読むための名前です。`latest` は「いちばん新しくビルドされたもの」で、
  内容は更新のたびに変わります
- **`LASER_IMAGE_DIGEST`** … その版そのものを指す固定の値です。**こちらを書くと中身が決まります**
  （名前は表示用になります）

**正式版を配布するときは、この 2 つを組にしてお渡しします。** 両方を `.env` に書いておけば、
更新のたびに中身が入れ替わることはありません。

> **正式版（v1）はまだ発行していません。** 上の `sha256:...` は書き方の例であって、
> 実在する版の値ではありません。正式版をお渡しするまでは `latest` のままで構いません。

---

## 前の版に戻す

**戻したい版の名前と digest を `.env` に書いて、インストーラをもう一度実行するだけです。**

```
LASER_IMAGE_TAG=（戻したい版の名前）
LASER_IMAGE_DIGEST=sha256:（その版の digest）
```

digest のほうが実体を決めるので、これを書いておけば**確実に同じものに戻ります**。
名前だけで戻すと、その名前が別のものを指すように変わっていた場合に、意図しない版になります。

データは触りません。戻したあとも参加者のデザインはそのまま使えます。

---

## バックアップ

**インストール先のフォルダを丸ごとコピーするだけです。**

| 機械 | やり方 |
|---|---|
| Mac / Windows | `laser-editor` フォルダを外付けドライブ等へコピー |
| Raspberry Pi / Linux | `sudo tar czf backup.tar.gz -C /opt/laser-editor data .env` |

### 何が入っているか

| 入るもの | |
|---|---|
| `data/` | 参加者のデザイン、スキャン、共有棚、設定 |
| `.env` | 管理トークンと設定 |

**取り込み済みの記録も一緒に保存されます。** これは重要で、復元したときに
「前に取り込んだ絵をもう一度取り込んでしまう」ことを防いでいます。

### 何が入っていないか

- ScanSnap の保存先フォルダ（**あなたの資産**です。LaserEditor は預かっていません）
- Docker Desktop / Docker Engine 本体
- 一時的な作業領域（作り直せるもの）

止めてからコピーするのがいちばん確実です（Mac / Windows なら Docker Desktop を終了、
Pi なら管理画面からシャットダウン）。

---

## 復元する

1. 新しい機械に、[各手順書](../README.md#どれを使えばいいか) のとおり **Docker を用意**する
2. **バックアップしたフォルダをインストール先に置く**（Pi なら `tar` を展開する）
3. **インストーラを実行する**

これで、デザイン・共有棚・設定・取り込み済みの記録が戻ります。
公開 URL も同じものが使えます（`tailscale-state` フォルダに身元が入っているため）。

**確認済み**: 実際の運用データで、コンテナごと消してから復元し、
共有棚と取り込み済みの記録が戻ること、同じ絵を入れ直しても二重にならないことを確認しています。

---

## アンインストール

**通常のアンインストールでは、参加者のデザインは消えません。**

| 機械 | 操作 |
|---|---|
| Mac / Raspberry Pi / Linux | `uninstall.sh` を実行（Pi は `sudo` が要ります） |
| Windows | `uninstall.bat` をダブルクリック |

何が消えて何が残るかを**先に見たいとき**は、確認だけして終わることもできます。

```bash
bash uninstall.sh --dry-run
```

### 消えるもの / 残るもの

| | |
|---|---|
| **消える** | LaserEditor のコンテナ、作業用の一時領域、設定ファイル（`compose.yaml`）、`管理トークン.txt` |
| **残る** | `data/`（参加者のデザイン）、`.env`、公開 URL の身元、**あなたが置いたファイル** |
| **触らない** | ScanSnap の保存先フォルダ、Docker Desktop / Docker Engine、Tailscale、LightBurn |

再びインストーラを実行すれば、**残っていたデータのまま**復帰します。

### データごと完全に消す

**取り消せません。** 必要ならバックアップを取ってから実行してください。

```bash
bash uninstall.sh --purge          # 確認を求められます
```

Windows は `uninstall.bat` に `-Purge` を付けて実行します。

イメージ（約 2GB）も消したい場合は `--remove-images` を付けます
（付けないと残ります。次に入れ直すときに再取得せずに済みます）。

## 1 台につき 1 つ

**LaserEditor v1 は、1 台の機械につき 1 つのインストールを正式対応とします。**

同じ機械に 2 つ入れることは技術的には可能ですが、片方をアンインストールするともう片方まで
止まります。対象外の構成なので、別々の機械に分けてください。

複数の機械に入れること自体は、正式に想定している使い方です。そのときは次を確かめてください。

---

## この機械の名前と公開 URL

インストール先の `.env` に、この機械の名前が 1 行入っています。

```
LASER_TS_HOSTNAME=laser-editor-1a2b3c4d
```

管理画面の「公開」（インターネット公開）を使うと、公開 URL はこの名前から決まります。

```
https://（この名前）.（あなたの tailnet）.ts.net
```

- 名前は**インストールのときに 1 度だけ**自動で決まります。更新しても入れ直しても変わりません。
- **書き換えると公開 URL が変わります。** 配布済みの QR は、その機械に届かなくなります。
- **2 台目を入れるときは、この行が 1 台目と違うことを確かめてください。**
  同じ名前の機械が 2 台あると、同じ公開 URL を取り合います。片方のために印刷した QR が、
  もう片方につながることがあります。

この行が無いインストールもあります（この仕組みができる前に入れたものです）。
その場合は `laser-editor` という名前のまま動いています。
**動いているものを変える必要はありません。** ただし 2 台目を入れるときは、
2 台目の側にこの行があることを確かめてください。

なお、[復元](#復元する)で別の機械へ**引っ越す**場合は、`.env` ごと持っていけば名前も
公開 URL もそのままです。

引っ越しではなく、バックアップを元に**2 台目を増やす**場合は、`.env` のこの行を
**手で別の名前に書き換えてください**（例: `LASER_TS_HOSTNAME=laser-editor-2f8b41c9`）。
インストーラは、既にある `.env` を書き換えません。1 台目と同じ名前のままにすると、
2 台が同じ公開 URL を取り合います。
